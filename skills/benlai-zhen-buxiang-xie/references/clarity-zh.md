# 中文清晰度规则

改编自 [ste-clarity](https://github.com/yfHHHE/ste-clarity) 的中文部分（MIT）。目标是让原意更清楚，不是把中文改成英文句式。

## 先说结论

每节、每段先写结论或要做的事，再写理由。去掉"针对……进行相关处理""为了更好地……"这类不承担含义的套话；不能删除实际的动作、责任或约束。

## 约束强度不随意改

| 原文用词 | 保护的含义 |
|---|---|
| 必须、须 | 不改成建议或可能 |
| 应、应当、应该、建议 | 保留原措辞；"应当"不自动弱化为"建议"，也不自动强化为"必须" |
| 可以、允许 | 区分许可、能力与可能性 |
| 不得、禁止、不应 | 保留各自强度；"不应"不擅自换成"不得" |
| 可能、预计、暂未、尚未、基本 | 保留不确定性；"基本完成"不等于"完成"，"暂未发现"不等于"没有" |
| 无需、不必 | 表示不要求，不等于"不得" |

PRD 里自己写的规则，用词要前后一致：同一类约束全文用同一个词。

## 条件、主体和范围

- 保留"仅当""除非""至少""至多""且""或"的逻辑关系。"仅当 A 才允许 B"限制 B 的前提，不要求一定执行 B。
- 保留否定词和它的作用范围。
- 中文可以省略已明确的主语；只在有依据时补全主体，不凭空写"由某团队负责"。
- "及时""尽快""合理""稳定"这类词缺少指标时，保留原要求并标 [待确认]，不凭空写毫秒数、负责人或阈值。

## 区分事实、假设、提案

| 类型 | 写法 |
|---|---|
| 已确认的事实 | 直接陈述，必要时注明来源 |
| 假设 | 写明"目前只是假设"，并标 [待确认] |
| 设计建议 | 标 [提案] |
| 推断 | 写明是推断，不写成根因或结论 |

没有数据支撑的趋势、根因、紧急程度一律不写。数据拿不到时写"暂不可用"，不写成 0 或"没有异常"。

## 结构跟着内容走

- 有先后顺序的用编号，并列的用列表，真正的对比用表格。
- 不为了整齐把每句话都拆成标题或表格。
- 术语全文统一：一个概念一个名字，第一次出现时解释。

## 改写用户原话时

保留事实、数量、单位、主体、顺序、条件、例外、否定、不确定性和约束强度。只澄清原文支持的内容；原文有歧义的，保留或单独标出，不替用户猜。
