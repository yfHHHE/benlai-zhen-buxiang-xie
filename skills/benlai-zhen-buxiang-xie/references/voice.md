# 语气与写法

用作者本人的口吻，第一人称，像在跟一起做事的同事说话。坦诚、直接、有判断，但不随意。

## 语气

- **第一人称表达判断**："我倾向于……""我的判断是……""这块现在的设计不太好，优先级可以先放低"。
- **坦诚面对取舍和精力**：可以说"这块先做轻""这个先不做，下期重点优化"。不卖惨，不推锅。
- **先讲为什么，再讲做什么**：价值、目标在功能之前。
- **中英混用按团队习惯**：句子用中文，产品名词、模块名保留英文（Dashboard、Widget、Onboarding 这类）。
- **用比喻点出阶段定位**，一句就够：如"上期是埋入 AI 的基因，这期要塑造骨骼"。
- 可以有一点口语和语气词，但正式交付给团队的版本不要用表情符号和网络梗。

## 写法习惯

- **模块标题写目的**：「订单模块：让用户一眼找到卡住的订单」好过「订单模块更新」。
- **需求用编号层级**：1 → a → i。一条需求一件事。
- **每个模块都有「特别注意」**：写边界、约束、容易做错的点。
- **明确砍掉的东西**："暂不支持""先不做，放到 Phase N""如果还有精力再做"。砍掉的要说明去哪了。
- **先定义概念，再写功能**：容易混的概念先讲清楚（如"组织 - 团队 - 成员"三者的关系和区别）。
- **按角色写需求**：每个角色一句话说明能做什么、不能做什么。
- **数据来源要透明**：哪些自动获取、哪些人工维护；数据时间和更新人要能看到。
- **前后端分工一句话说清**：如"后端计算所有指标，前端只展示""前端的权限判断只影响展示，后端每个请求独立校验"。
- **开放问题就地标出**：在句子里直接标 [待确认]，并在文末汇总。

## 示例对照

| 不像 | 像 |
|---|---|
| 本模块旨在为用户提供全面的订单管理能力。 | 这期的目标就一个：让用户一眼找到卡住的订单，知道下一步找谁。 |
| 系统将实现消息通知功能，满足多种业务场景。 | 本期只做站内信。其他推送渠道等流程建好了再串上。 |
| 可考虑后续迭代中优化。 | 这块先不做，放到 Phase 3。 |
| 根据某某的要求，…… | （不点名，直接写成产品决定）…… |
| 预计提升效率 50%。 | 收益阈值拿到基线后再定。 |
